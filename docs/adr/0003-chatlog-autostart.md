# ADR-0003: chatlog 常驻采用开机自启（Startup 目录）

- **状态**：Accepted
- **日期**：2026-08-24
- **决策者**：MVP-AI-Secretary-Requirements V0.2（决策②）

## 上下文与背景

微信采集层依赖 chatlog 本地 HTTP 服务（`127.0.0.1:5030`）提供增量拉取与 Webhook 能力。
若服务不常驻，采集链路会因进程退出而中断；MVP 要求系统"每晚生成次日计划 + 实时识别时效性消息"，
采集服务必须持续可用。此前缺口"5030 服务未常驻"已确认，需拍板常驻方式。

## 决策

**chatlog 采用开机自启方式常驻**：在 Windows 启动目录（Startup）放置
`chatlog_autostart.vbs`，隐藏窗口启动 `chatlog.exe` v0.5.2；运行依赖微信登录态。

来源：MVP-AI-Secretary-Requirements.md §5 决策②、§3.1（缺口①已落地）。

## 考虑过的选项

| 选项 | 说明 | 否决/采纳理由 |
|------|------|--------------|
| 开机自启（Startup VBS） | 启动目录放 VBS，隐藏窗口拉起 chatlog，登录后自动就绪 | 采纳：已落地（127.0.0.1:5030 常驻） |
| 手动按需启动 | 需要时手动运行 | 否决：无法支撑实时采集与每晚规划闭环 |
| 计划任务（Task Scheduler） | 系统级计划任务常驻 | 否决：VBS 方式已满足且更轻量，避免额外复杂度 |

## 后果

### 正面影响

- 采集服务开机即就绪，满足实时通知与每晚规划的时间约束。
- 隐藏窗口启动不干扰用户桌面。

### 负面影响与代价

- 依赖微信登录态，微信退出登录后需重新登录恢复采集。
- 开机自启常驻进程增加后台资源占用（可接受，chatlog 为本地轻量工具）。
