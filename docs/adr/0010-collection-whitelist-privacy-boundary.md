# ADR-0010: 消息采集采用白名单，并限定送模型的数据边界

- **状态**：Accepted
- **日期**：2026-08-24
- **决策者**：MVP-AI-Secretary-Requirements V0.3（决策⑨）
- **关联**：ADR-0003（chatlog 常驻）、ADR-0005（规则+模型识别）、ADR-0011（分层模型路由）

## 上下文与背景

chatlog 以本地数据库直读方式**解密全部微信消息**（`auto_decrypt: true`）。而识别链路中的「模型确认」步骤会把消息内容发送给云端模型 API（当前 L2 使用便宜云模型，L1 为 Kimi K3）。

若不设边界，默认行为等价于**把全部私人聊天送第三方**——包括家人、伴侣、与项目完全无关的会话。这既是隐私风险，也是不必要的模型成本：MVP 真正需要的日程来源只有少数几个群与联系人。

此前需求文档只登记了「微信 ToS / 封号风险」，未登记数据出境边界，属风险登记缺口。

## 决策

**采集采用白名单：只采集用户点名的群/联系人；并对送模型的数据设三条硬边界。**

1. **白名单采集**：仅拉取配置中列出的 `talker`（群/联系人）。未列出的会话不入库、不过规则、不送模型。
2. **规则过滤只在本地**：关键词/时间表达式匹配（`vaelis/agenda/rules.py`）不得调用任何 LLM。
3. **只送命中片段**：仅将命中的**单条消息片段**发送给模型确认，不发送整段对话历史；`events.evidence` 同样只存该片段。

结构上支持黑名单（默认全量采集 + 排除指定会话），但 MVP 默认走白名单。风险登记新增「隐私外泄」为高等级条目。

## 考虑过的选项

| 选项 | 说明 | 否决/采纳理由 |
|------|------|--------------|
| 白名单采集 | 只采点名会话 | 采纳：隐私暴露面与误报噪音同时最小，模型成本也最低 |
| 全量采集 + 命中才送模型 | 本地全量入库，仅命中片段出境 | 否决为默认（保留为后续放宽路径）：本地库仍聚合全部私人对话，且误报噪音大 |
| 全量采集 + 黑名单 | 默认全采，排除敏感会话 | 否决为 MVP 默认：黑名单是"漏一个就泄露"的失败模式，MVP 阶段不承担 |
| 无边界（全量送模型） | 最简单 | 否决：隐私风险不可接受，成本亦不可控 |

## 后果

### 正面影响

- 隐私暴露面从"全部微信"收窄到"少数几个群"。
- 模型调用量大幅下降，直接降低运行成本。
- 误报噪音下降，使 ADR-0009 的「待确认」不至于变成骚扰。

### 负面影响与代价

- 白名单外的日程信息会被漏掉，需要用户维护名单；漏配时表现为"系统没看到这件事"。
- 名单维护是持续性人工成本，需要在看板或配置中提供便捷的增删入口。
- 后续若放宽为"全量 + 黑名单"，需重新评估本地库的敏感数据聚合风险。
