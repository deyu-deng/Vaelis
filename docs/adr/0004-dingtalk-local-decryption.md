# ADR-0004: 钉钉接入采用本地解密第三方手段

- **状态**：Accepted
- **日期**：2026-08-24
- **决策者**：MVP-AI-Secretary-Requirements V0.2（决策③）

## 上下文与背景

钉钉是用户社交消息来源之一，MVP 采集层需覆盖钉钉消息。但学校组织无开放平台 API/CLI 权限，
无法通过官方接口获取消息。需在合规与可行性之间选择接入手段，且不阻塞 MVP 主链路。

## 决策

**钉钉接入必须采用第三方手段——本地解密**：参考开源方案 `dingtalk-exporter`
（离线解密 V2/V3 加密 SQLite、WAL 增量同步、每 4 小时自动同步、AI 友好 JSON 导出、附件 ZIP 打包）。
MVP 阶段仅预留统一采集接口 `collect_dingtalk()` 抽象，代码不落地，不阻塞主链路。

来源：MVP-AI-Secretary-Requirements.md §5 决策③、§3.2。

## 考虑过的选项

| 选项 | 说明 | 否决/采纳理由 |
|------|------|--------------|
| 本地解密第三方手段 | 参考 dingtalk-exporter 离线解密本地库 | 采纳：学校无 API 权限下的可行路径，MVP 预留接口 |
| 官方开放 API | 学校组织无开放平台 API 权限 | 否决：权限不存在，不可行 |
| 官方 CLI | 同样受组织权限限制 | 否决：无 CLI 权限 |

## 后果

### 正面影响

- 钉钉采集路径保留，后续可扩展，不阻塞 MVP 主链路（微信 chatlog 先行）。

### 负面影响与代价

- 本地解密涉及账号数据读取，需注意合规与账号安全风险（与微信同类风险一致，仅本地读库解密）。
- 方案未落地，正式接入前需另行验证代码实现。
